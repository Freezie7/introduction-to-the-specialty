# Финальный отчёт по проекту KIE AI Image Generator

## 1. Описание системы

Веб-приложение для генерации изображений по текстовому описанию (промпту) с использованием нейросетей KIE AI.

Пользователь вводит промпт → бэкенд отправляет задачу в KIE AI API → фронтенд polling'ом ждёт результат → отображает готовое изображение.

## 2. Архитектура
Frontend (HTML/CSS/JS)

↓ fetch

Backend (Node.js/Express)

↓ REST API

KIE AI API (модель nano-banana-2)

**Frontend** — статические файлы, Vanilla JS, polling каждые 3 секунды.  
**Backend** — прокси-сервер, скрывает API-ключ от клиента.  
**KIE AI** — внешний сервис генерации изображений.

## 3. Тестирование

Использован фреймворк **Jest** (unit-тесты).

Тестируется функция `extractImageUrl` — парсинг ответов от KIE AI API:

| Тест | Результат |
|------|-----------|
| Извлечение url из поля imageUrl | ✅ Pass |
| Извлечение url из вложенного data | ✅ Pass |
| Извлечение url из массива output | ✅ Pass |
| Возврат null если url отсутствует | ✅ Pass |

Запуск: `npm test`

## 4. CI Pipeline

GitHub Actions запускается автоматически при каждом Pull Request.

Три job'а:
- **lint** — ESLint проверка `server.js` + запуск Jest тестов
- **semgrep** — статический анализ кода на уязвимости
- **trivy** — сканирование зависимостей на CVE-уязвимости

## 5. Безопасность

**Semgrep** — анализирует исходный код на паттерны уязвимостей: инъекции, небезопасные функции, плохие практики.

**Trivy** — сканирует `package.json` и `node_modules` на известные CVE в сторонних библиотеках.

**Архитектурно** — API-ключ хранится в `.env` на сервере, никогда не передаётся клиенту.

## 6. Docker

Бэкенд упакован в Docker-контейнер на базе `node:20-alpine`.

```bash
docker build -t kie-backend ./backend
docker run -p 3100:3100 -e KIE_API_KEY=ключ kie-backend
```

Обеспечивает воспроизводимость запуска на любой машине.

## 7. Выводы

В ходе проекта реализован полный цикл разработки веб-приложения:

- Проектирование архитектуры и написание README
